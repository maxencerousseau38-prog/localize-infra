# Awesome Design MD

Use this skill as a design-reference library, not as a visual identity generator.

Before making substantial UI or landing-page changes:

1. Read the repository's DESIGN.md and CLAUDE.md.
2. Identify the product's existing visual identity, tokens, typography, semantic colors, State Rule, accessibility rules and responsive rules.
3. Select only relevant references from ./design-md/.
4. Prefer references such as:
   - stripe
   - linear.app
   - vercel
   - framer
   - apple
   - supabase
   - github where available
   - raycast
   - resend
   - replicate
   - mintlify
5. Read the actual DESIGN.md files before implementing.
6. Extract principles, architecture, hierarchy, density, interaction patterns and composition.
7. Do NOT copy colors, branding, logos, typography or visual identity from the references.
8. Preserve the existing Localize Infra identity and tokens.
9. Combine useful principles from multiple references rather than reproducing one company's design.
10. Every substantial design change must have a clear product, narrative, usability or conversion reason.

The goal is to use the references as design intelligence while making Localize Infra unmistakably its own product.

Never claim a reference was used unless its actual DESIGN.md was read.
